# iOS購入修正・ビルド21（2026-10-01）

## 原因と修正

写真の11:10〜11:12に対応する本番 `apple-purchase` ログで、ビルド20の要求が `transaction_ownership_conflict` として拒否されていた。Apple取引の署名検証は通ったが、取引の `appAccountToken` が現在ログイン中のアプリアカウントと一致していなかった。確認時のApple取引台帳は空で、完全版の付与に至っていない。

ビルド20のソースには別チェックアウトで作成済みだった過去取引の除外と円表示が取り込まれていなかった。ビルド20の保守・通信量改善を保ったまま、以下を統合した。

- 別アプリアカウントの過去取引を購入イベント・復元・直接検証で除外する。未ログインの再送も検証しない。他アカウントの権限を移したり、その取引を完了扱いにしたりしない。
- 承認待ち・購入済みイベントも現在のアカウントで判断する。検証していないイベントで購入成功を通知しない。
- サーバーの所有者不一致等の応答を読み、対応する日本語の説明を出す。商品取得と復元でネイティブ例外をそのまま表示しない。
- 購入直前に商品情報を再取得し、取得失敗後も画面の再読み込みを利用できるようにする。
- iOS専用価格を320円（税込）とし、紹介・購入カード・購入ボタンの3か所とiOS販売条件を揃える。

App Store Connectの非更新商品 `jp.shoseijutsuroku.app.complete30days`（Apple ID `6810376972`）の日本価格を280円から320円へ即時変更した。保存後の「現在の価格」で日本（JPY）￥320.00を確認済み。証拠は `.expo/apple-price-320.png`。App Storeの購入確認画面の通貨はAppleのストア環境に従う。

本番バックエンドには以前の修正（P-256のWeb Crypto署名、認証済みSandbox購入、診断ログ）が既に配布されていた。現行の配布ソースと照合してローカルへ取り込み、古いNode署名実装へ戻さないようにした。今回、バックエンドの再配布・取引台帳の変更は行っていない。
