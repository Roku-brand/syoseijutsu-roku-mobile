# 開発・保守・運用

## 作業を始める

アプリの Git リポジトリは、この README と `package.json` が置かれたフォルダーです。親フォルダーには旧版や別作業のチェックアウトがあるため、毎回 `git status --short --branch` で対象を確認します。未コミットの変更を別作業の変更で置き換えないでください。

CI と同じ Node.js 22（TypeScript の実行に対応した 22.18 以降）と pnpm 10 を使います。依存関係を更新しない通常の開発では、次のコマンドでロックファイルを維持します。

```sh
pnpm install --frozen-lockfile
pnpm check
pnpm start
```

`pnpm check` は型検査、単体テスト、`operations/*.json` の検証を実行します。ネットワーク上のデータを書き換えません。PR の CI でも同じコマンドを実行します。

## 個人データの状態管理

| ファイル | 責務 |
| --- | --- |
| `src/state/app-state.tsx` | React の公開 API、画面への通知、触覚フィードバックと保存イベント |
| `src/state/app-state-model.ts` | データ型、初期値、旧データの復元、純粋な状態更新 |
| `src/state/state-persistence.ts` | 読み込み、起動待ち時間、編集の再適用、保存・消去の順序 |

画面からは既存の `useAppState()` を利用します。新しい操作は model の `AppStateAction` と `reduceAppState` に追加し、provider から dispatch します。モデル内では時刻取得、ストレージ、ネットワーク、React を使用せず、ID と時刻を action に渡します。

保存キーは既存の `@shoseijutsu-roku/state/v1` を維持しています。復元では対応フィールドだけを採用し、値の型を確認します。旧文字列メモはオブジェクトへ変換し、削除済みフォルダーへの参照は外します。管理画面で追加された関心カテゴリも保持します。学習カリキュラムの変更時は `LEARNING_CURRICULUM_VERSION` を更新し、旧学習記録のみをリセットします。

起動時に読み込みが 900ms を超えた場合は画面を先に表示しますが、ストレージの読み込み完了までは保存しません。その間の編集は読み込み完了時に復元データへ再適用します。保存操作は「保存する／外す」の意図を記録し、既に保存済みのデータを誤って反転しないようにします。

保存・消去は同じキューで順番に実行します。消去後に古い読み込み結果が返ってもデータを復活させません。保存の失敗は捕捉し、後続の保存を止めません。

## 不具合調査

ログの `Personal state storage operation failed:` に続く `read` / `write` / `clear` で失敗箇所を識別できます。ログにはメモ本文や保存データを含めません。

- `read`: 端末の保存領域へのアクセスや JSON の読み込みに失敗。既存データを守るため自動上書きを停止し、そのセッションの編集は画面内だけに保持します。再起動やブラウザーの保存設定を確認してください。
- `write`: 容量制限や保存領域へのアクセスを確認。後続の編集で保存を再試行します。
- `clear`: 画面に消去失敗を表示します。端末内データの消去を完了したとは判断しないでください。

調査のために保存領域全体を消去するとユーザーの個人データが失われます。データ消去は本人が設定画面で明示的に選択した場合にだけ行ってください。

## リリース前の確認

```sh
pnpm check
pnpm export:web
node scripts/audit-public-build.mjs
pnpm test:e2e
```

Web の出力は `dist/` です。ビルドは公開カタログと PWA キャッシュを再生成するため、`git diff` で生成ファイルの差分を確認します。`dist/` の古い出力を使ったテストは変更後の検証になりません。

Windows の OneDrive 配下では、通常ファイルのディレクトリエントリーがリンクとして扱われ、Expo のファイル一覧処理が存在する `expo-router/entry.js` を解決できないことがあります。同期領域外のチェックアウトへ同じソースを用意し、`pnpm install --frozen-lockfile` で依存関係を配置して確認してください。型検査が通っても、この問題で Web ビルドは失敗する場合があります。原因を確認せずにルーターの設定やパッケージのバージョンを変更しないでください。

個人データ周辺の変更では、保存、再読み込み、メモ編集、フォルダー削除、データ消去を Web と対象端末で確認します。読み込み遅延、JSON 破損、保存失敗、消去と読み込みの競合は `tests/unit/state-persistence.test.mjs` で再現できます。

公開手順は [リリースチェックリスト](../RELEASE_CHECKLIST.md)、コンテンツ管理は [CMS の説明](content-cms.md)、オーナー業務は [運用手順](owner-operations.md) を参照してください。ローカルの検証コマンドと、外部のデータや公開環境を変更する `operations:sync`・`content:sync-paid`・デプロイは区別して実行します。

Supabase の通信量、取得列、キャッシュの有効期間と更新反映の扱いは [通信量最適化の記録](supabase-usage-optimization-20261001.md) を参照してください。
