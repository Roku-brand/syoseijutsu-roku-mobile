# ホームデッキの表示・動作・起動処理の改善

## 変更

- 英語の種類表記を、処世術では既存の人物像名、理論では既存の理論分類へ変更。長い名称は1行に収め、読み上げ用の名称も設定。
- 逆送りは最下段のカードを左から引き出し、外側で最前面へ移して手前へ戻す。順送りと同じ軌道を逆順に通り、左右の操作と履歴の意味は維持。
- 入れ替えは5枚を左右へ送り出し、全カードが隠れてから5枚を交換。反対側から奥のカード、手前のカードの順に配る。Webは約560msのブラウザ管理アニメーション、ネイティブは600ms。途中の連打を防ぎ、動きを減らす設定へ切り替えても交換は一度だけ。
- 保存デッキと個人情報を並列で読み込み、CMS上のID復元時は起動中の公開カタログ取得を共有。CMSからの明示的な再取得は引き続き新しいリクエストを開始する。
- 推薦計算は全候補の反復ソートから最良候補の選択へ変更。日替わり・絞り込み・履歴・保存の重み・同一シードの順序は維持。
- 初期カタログのタグ補完は同じ結果の先頭3件だけを計算し、表示名の再正規化を省略。
- 最初のホームカードが操作可能になった時点で起動カバーを閉じる。画像待ちによる余分なカバー表示を減らし、従来のタイムアウトも維持。カード画像には同じ寸法の既存画像をプレースホルダーとして使用。

共通ヘッダー、全幅リール、5つのショートカット、完全版LP、ナビゲーション、アクセス制御は変更していない。画像生成・新しい画像アセットの追加はなし。

## 計測

ローカルNodeで同一入力を反復した中央値。端末全体の起動時間ではない。

| 計算 | 変更前 | 変更後 | 結果の同一性 |
| --- | ---: | ---: | --- |
| 5枚の推薦（無料版） | 約16.3ms | 約2.4ms | 同じ5ID・順序 |
| 5枚の推薦（完全版） | 約16.3ms | 約1.7ms | 同じ5ID・順序 |
| 356処世術のタグ補完 | 約26.4ms | 約15.1ms | 356件すべて一致 |

画像1件を意図的に遅延したローカルChromiumでは、通常CPUの起動カバー解除の中央値が約2.28秒から約1.27秒になった。各3回の参考値で、キャッシュ・通信・端末性能によって変わる。CPUを4倍低速にした条件ではアプリ全体の初回JS処理・描画に待ちが残り、今回の変更による全体起動時間の短縮は確認できていない。

## 検証

- デッキ・推薦単体19件、検索関連単体9件、検索タグ移行検証を実施。
- Web/iOSのエクスポート、TypeScript、Lint、差分チェックを実施。
- Chromiumで順送り・逆送り・ドラッグキャンセル・保存・詳細復帰・日付変更・CMS遅延復元・全5種類の全交換を確認。
- 追加のブラウザテストで、5枚の退出/入場軌道、演出途中の動き設定変更、画像待ち中の起動カバー解除、公開カタログ取得が1回であること、CMSの人物像名/理論分類の反映を確認。
- 最終のWebKit回帰検証、レスポンシブ画面確認、公開ワークフローの結果はPRに記録する。

iOSはバンドル生成まで検証。iOS実機のネイティブアプリ操作はこの環境では未検証。
