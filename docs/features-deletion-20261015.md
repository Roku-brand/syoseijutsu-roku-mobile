# 特集管理の削除・非公開

- 既存の非公開操作を維持。本文と保存済みの下書きを残して読者画面から外す。記事名を確認画面に表示する。
- 公開中・非公開・下書きの保存済み記事に「削除する」を追加。記事名と復元不可の説明を確認してから実行する。未保存の変更がある間は操作を無効にする。
- オーナー専用の delete_feature_article RPC を追加。記事の更新版と下書きのリビジョンが一致する場合のみ削除する。既存のRLS・権限を再利用し、カラムやテーブルは追加しない。
- 記事と対応する下書きを削除し、他の記事・下書きの関連特集IDから削除対象のみを外す。他の記事のタイトル、本文、画像、URL、知識IDは保持する。同時編集の旧版は受け付けない。既に競合している下書きの基準版は勝手に修復しない。
- 共有される可能性のある画像ファイルは削除しない。既存の未使用画像管理を利用する。
- 既存の実記事は削除しない。DBテストは検証記事を作成しトランザクション全体をロールバックする。ブラウザテストはモック記事のみで行う。

検証：独立Postgres互換環境でマイグレーション、公開・非公開・下書きの削除、記事／下書きの競合、関連リンク整理、再公開、他記事の保持、非オーナー／匿名の拒否を確認。ブラウザで確認・取り消し・削除・競合エラーと公開一覧への反映を確認。
