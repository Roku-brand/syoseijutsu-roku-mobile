## Phase 2–3 推奨方針・リスク・Web影響

1. Expoを維持。iOS専用upgradeとStoreKitライブラリ、共通APIにApple権限を追加。既存Stripeのgrant/refundを書き換えず、Apple台帳を分離して共通read RPCで合成する。Web entitlementとApple entitlementの返金を相互に波及させない。
2. Non-Renewing Subscriptionを採用。Consumableは使い切り、Non-Consumableは期限なし、Auto-Renewableは自動更新のため現仕様に不一致。Appleの取引日時から厳密な30日、再購入でも過去取引の再送は延長しない。Apple商品価格はStoreKit表示価格を使用し、JPY 280の選択可否はASC登録時に確認。勝手に値上げしない。
3. 3.1.1 IAP、3.1.3(b) multiplatform：Web既存権限でログイン利用可能、同一内容をIAP提供。日本代替決済entitlementは追加しない。iOSのStripe/PayPay購入誘導を排除。
4. Apple公式Server LibraryでJWSの証明書チェーン、bundle、environment、appAppleIdを検証。Server APIで最新取引を取得しappAccountTokenを認証UUIDへ照合。client成功のみで解放しない。通知V2と再照合で返金、重複、再送、逆順を処理。
5. 非自動更新の復元は同じアプリ内アカウント+サーバー台帳を基本としStoreKit履歴も再検証する。別アカウントへの移転は拒否。
6. 5.1.1(v)削除、5.1.1 privacy、4.8認証、4.2 minimum functionality、2.1 completenessを重点確認。既存ネイティブ検索・保存・ケース学習は価値だが審査合格の保証はできない。
7. Web URL/SEO/PWA/Stripe/PayPay/公開checkoutを変更せず、native分岐と追加ファイル中心。DB read RPC合成は共通のためSQL検証とstagingが必須。未検証migrationは本番適用しない。
