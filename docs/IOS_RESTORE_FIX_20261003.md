# ビルド24の復元エラーとソース修正

## 確認した現象

2026-10-03、ビルド24のv2商品でSandbox購入が記録され、ユーザーが人物像から完全版の本文を表示できることを確認した。その後「購入履歴を復元する」を押すと、完全版を利用中の表示と同時に「App Storeから購入結果を取得できませんでした」が出る画像が届いた。ユーザーは復元ボタン直後のエラーと明示した。

DBのv2取引は購入2026-10-03 11:14:08 JST、期限2026-11-02 11:14:08 JST、有効・失効なし。データや利用期限は変更していない。

## 原因と変更

旧処理は端末のStoreKit復元を先に実行し、それが失敗するとサーバーに保存済みの購入再検証まで到達しなかった。Apple端末照会のエラー自体の根本原因は、この画像だけでは確定できない。

`restoreApplePurchases` をサーバーでの保存済み取引再検証から開始し、その後のサーバー利用状態がactiveなら完了する順序へ変更した。サーバーの既存 `refreshAppleTransactions(user.id, true)` はAppleの署名済み取引、商品、購入者、返金を再照合する。端末の表示・キャッシュを利用権として信頼する変更ではない。

有効な保存済み利用権がない場合は、端末StoreKitの履歴から未反映の購入を回収する。別アプリアカウントの履歴をスキップし、検証後にのみ取引を完了する既存処理は維持した。

購入ページは利用状態の確認中・完全版利用中には不要な商品読み込みを開始しない。無料状態が確定した時点で商品を取得する。新規購入、商品ID、価格、30日間の期限、法的表示は変更していない。

## 検証と公開状態

- 修正前のテストで、保存済み利用権が有効でも端末復元エラーで停止するケースを再現。
- 修正後、既存購入処理を含む全53件の単体テスト成功。サーバー検証の失敗を成功扱いしないこと、未反映購入の回収、所有者の照合を検査。
- TypeScriptの型チェック成功。
- ローカルiOS JavaScriptのエクスポート成功（1,882モジュール）。ソースマップで復元処理と購入画面が修正後のソースと完全一致し、v2商品IDが維持されることを確認。これはクラウドのネイティブビルドではない。
- ソース修正のみ。ビルド24の配信済みIPAは変更されていない。新規EAS Build、TestFlight再配信、App Review提出は行っていない。

以前の明示許可はビルド24の再実行1回までだったため、この修正をiPhoneへ配信する新ビルドは別途確認する。実機の復元成功と、最新OSでの審査動画の不足は未解消として扱う。
