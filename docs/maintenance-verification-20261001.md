対象: `theory-rights-release` 内の `codex/maintenance-refactor-20261001`。基準コミットは `8d98bae`（main のランキング更新と、その E2E 設定修正を含む）。他のチェックアウトの作業中変更は対象外です。

## 変更

- 約480行に集中していた個人状態の管理を、React の公開 API、復元・更新ルール、ストレージ制御に分離。
- 保存キーと `useAppState()` の画面向け API を維持。
- 読み込みの遅延中は初期値を書き込まず、読み込み完了時にその間の編集を再適用。
- 保存・消去を順序制御し、消去後の遅い読み込みによるデータ復活を防止。
- JSON 破損・読み込み失敗時に既存データを自動上書きしない。消去失敗は設定画面で通知。
- 旧メモを移行し、不正な型、廃止フィールド、重複、無効なフォルダー参照を復元時に整理。追加された関心カテゴリを保持。
- メモ・フォルダー ID の同一ミリ秒内の衝突を回避。
- `pnpm check` を追加し、PR CI でも型・単体・運用データを検証。依存関係の導入はロックファイルを固定。
- 古いカテゴリ仕様を参照して起動できなかった既存の単体テストを現行仕様へ修正。

## ローカル環境の制約

OneDrive 内の通常の依存ファイルについて、`readdir` のエントリーはリンクと判定され、同じファイルの `lstat` は通常ファイルと判定されました。Expo のファイル一覧処理が前者を使うため、存在する `expo-router/entry.js` の解決に失敗します。キャッシュ再生成でも解消しませんでした。

そのため Web ビルド・ブラウザー検証は一時フォルダーへコピーした同じソース・同じ依存関係で実行しました。検証対象ソース5ファイルの SHA-256 が作業フォルダーと一致することを確認しています。コピー側の pnpm 実行時に自動インストールが走るため、ビルドの各スクリプトと Expo CLI を Node から順に実行しました。ブラウザー検証用サーバーも `node scripts/serve-dist.mjs` で起動しました。

本番 API の接続先にはダミー設定を使用しました。データベース、購入情報、公開環境の変更やデプロイは行っていません。

保守時のコマンドと障害調査は [保守ガイド](maintenance.md) を参照してください。
