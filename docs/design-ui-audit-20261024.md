# 処世術禄 デザイン・UI監査

監査日：2026年10月24日（日本時間）  
対象：公開Web版 `https://app.shoseijutsuroku.com/`、公開時点の main `a704a9978edd70bdab13d15ddac3409b361266a9` と対応するローカル実装。

## 判断

和紙、明朝、墨、金線という素材は揃っている。一方で、各画面が別々の完成基準で作られており、写真メディア、装飾的なカード集、学習ゲーム、個人用の管理画面を行き来している印象になる。色・文字・余白・操作表示の共通ルールが弱い。

特に完成度を下げているのは、読みづらい小文字、目的のない余白、意味が伝わらない保存アイコン、実際と食い違う説明、仮データや編集記号の露出である。画像の追加よりも、こうした細部の修正の効果が大きい。

このアプリの中心は「知識を手元に蓄積すること」と「思いがけない知識に出会うこと」。監査では、知識そのものの見つけやすさ・読みやすさ・保存と再発見の確かさを優先した。

## P1の具体的な修正条件

### A01：小文字を増やして収めない

ホームは `Math.max(7.5, Math.min(9, (width - 60) / 35))` により320px幅で7.5pxになる。ヘッダーの副題も10px、学習のCASE/STAGEも9px・8.5px。小さい明朝文字、薄い金・灰色、短い行間が重なる。

ホームの5項目は、短い表示名・2行ラベルなどで読める大きさを確保する。通常の操作名は13px前後、補足も原則12px以上を基準とし、長い題名は文字を小さくするより折り返す。320pxで収まることと、320pxで読めることを別々に確認する。

根拠：`src/app/(tabs)/index.tsx:78`、`src/components/book-ui.tsx:716`、`src/app/learn/[caseId].tsx:425`、同`:434`。

### A02：保存を同じ意味で伝える

お気に入りの空状態の「ハート」は実画面にも残っている。保存ボタンは `SaveDiamond` の菱形で、検索で押した際の通知は「蔵書に保存しました」。アプリの主要な蓄積動作なのに、見た目・説明・呼び名が一致していない。

保存の形は一種類に固定し、未保存と保存済みを形の塗りだけに頼らず伝える。菱形を維持するなら、詳細では「保存」「保存済み」の短い文字を添える案が適切。空状態、トースト、読み上げ名も「お気に入り」または「保存」に揃える。

根拠：`src/components/library-content.tsx:46`、`src/components/save-diamond.tsx:4`、`src/components/technique-row.tsx:13`、`src/components/theory-archive-card.tsx:13`。

### A03：仮の題名を完成したカードに見せない

320px幅で公開版を再読込した後、おすすめの対人術・仕事術・人生術が「完全版の処世術」と表示された状態を確認した。完全版ユーザーにはカードを区別する手がかりがなく、読み込み中なのか、公開されていないのかも分からない。

取得失敗の原因までは本監査では切り分けていない。確認できたUI上の問題は、データ未取得の状態を通常の完成カードとして見せていること。表示可能な知識で棚を構成し、未取得分には読込表示または復旧操作を出す。取得後は同じ位置のカードが安定して実題名になることを確認する。

根拠：公開版のおすすめを複数回確認。`src/data/reading-recommendations.ts:55` の候補選択、`src/app/(tabs)/index.tsx` の `ContentCard`。

### A04：本文の記法を正しく描画する

「本当の頭のよさとは何か」で、章の間の `---` がそのまま本文として表示される。本文レンダラーには見出し・箇条書き・引用の分岐があり、区切り線の分岐がない。

水平区切りとして描画するか、章見出しの余白に置き換える。記事を追加する際、使用できる記法の範囲と実表示を一緒に確認できる運用にする。

根拠：`src/components/feature-article.tsx:20`。

### A05：知識をつなぐ操作を小文字の図に埋めない

スマホのモーダルで2本だけの関連を上下に置き、その図に500pxを使っている。関連の説明・読む操作はその下にあり、モーダル内スクロールが必要。少ない関連を読む場面でも、図の空白が中心になっている。

スマホでは「いまの知識 → つながる知識 → 関係の説明 → 読む」を短い距離に収める。図は件数に応じて縮めるか、補助表示にする。PCには図を活かす余地がある。関連カード、ID、関係の説明は維持する。

根拠：`src/components/theory-network.tsx:66`、同`:95`。

### A06：一覧を開いてから知識が見えるまでを短くする

理論一覧は最初のカードが約525pxから始まり、390×844の画面では一枚目を見渡すだけで縦の大半を使う。分類は4列のうち2行目の先頭が空き、ページ番号は10個を2行で並べる。件数にも見出し相当の大きさが与えられている。

分野タブ、件数、ページ操作を一まとまりにする。ユーザー指定の理論の青・処世術の金、ID、理論専用のカード表現とページ選択は保ち、余白と配置を調整する。最初の画面から複数の題名を比較できることを基準にする。

根拠：`src/app/theories/index.tsx:78` 以降、`src/components/theory-catalog.tsx:22`、`src/components/pagination.tsx`。

### A07：PCでは広げる場所を決める

理論詳細の題名・解説・理論情報は820pxの中央列だが、関連一覧とボタンは外側の幅まで広がる。パンくずも外側の基準線。理論一覧の一枚も約1,000pxに広がり、短い題名と小さな要約の周りに大きな空白ができる。

本文・関連・出典を同じ読み幅に揃える。一覧では最大幅やPC用カード配置を別に決める。学習画面も、広いカードの中の11pxのケース一覧が取り残されて見えるため、文字と情報配置を同時に調整する。

根拠：`src/app/theory/[id].tsx:183`、同`:194`、`src/components/related-content-list.tsx`、`src/app/(tabs)/learn.tsx:125`。

### A08：禄丸の居場所を固定する

CASE 01の回答前画面では、右下の禄丸と背景の円がCの回答領域と下の注意書きに重なる。回答はまだ押せそうに見えるが、装飾が操作面に侵入しており、丁寧に整えた画面に見えない。

回答選択肢の外側にキャラクターの場所を確保する。小型画面や文字拡大時はサイズか表示位置を変える。禄丸は学習の案内役として維持し、本文・選択肢・結果の説明を覆わないことを条件にする。

根拠：`src/app/learn/[caseId].tsx:455`、同`:457`。

### A09：保存棚の絞込みを見える状態にする

マイページで「仕事術 0件」を開くと `/library?category=work` になる。しかし画面は通常の「お気に入り」、種類は「処世術」、件数は0件で、仕事術という条件が表示されない。対人術に保存がある環境でも「処世術のお気に入りはまだありません」と言われる。

現在の条件を「仕事術」のチップや見出しで示し、「すべての処世術」に戻す操作を置く。空状態も「仕事術にはまだありません」と範囲を正確に説明する。お気に入りの3種類切替とマイページの現在のプレビュー構成は維持する。

根拠：公開版 `/library?category=work`、`src/components/library-content.tsx:30`、同`:40`、同`:45`。

## 揃えるべきデザインの基準

目指す印象は「毎日めくる、上質な知識帳」。静かな紙面の上で言葉が読みやすく、気になった一枚を自然に保存できる状態を基準にする。

| 要素 | 共通ルールの案 |
| --- | --- |
| 色 | 本文は墨色。金は重要な操作と装飾。分野色は識別に使い、検索・保存の同じ種類切替には同じ規則を使う |
| 書体 | 見出しと知識本文は読みやすい明朝、操作と細かな情報はゴシックを中心に役割を分ける |
| 文字 | 本文16〜17px、一覧題名17〜20px、通常操作13〜14px、補足12px以上を出発点とする。短い画面で小文字へ逃がさない |
| 余白 | 8pxを基本に、部品内12〜16px、区画間24〜32pxへ整理。広い空白は区切りや読書のために使う |
| 枠 | 通常のカードは細い単線、表紙・ヒーローだけ装飾を許す。理論の二重枠は固有の表現として残し、他の場所に装飾を重ねすぎない |
| 角丸 | 通常カード・入力・モーダルで役割ごとの段階を決める。丸い操作タブと四角い理論カードの違いは意図を持たせる |
| 写真 | 分野の案内写真と記事専用表紙を区別。色温度・明暗を揃え、同じ写真を大量の知識の識別子にしない |
| アイコン | 保存・共有・編集・設定の造形と太さを統一。主要操作は必要に応じて短い文字も表示 |
| 操作領域 | アイコンの見た目と押せる領域を分け、44px程度の操作面を確保する |
| PC | 本文は740〜820px程度の共通列、一覧・ダッシュボードは別の最大幅。本文途中で列を変えない |
| 空・読込・失敗 | それぞれ固有の説明と次の操作を用意。データがない理由を見た目で判別できるようにする |
| 動き | 出会いを生むカード切替は活かす。読んでいる時間、操作中、動きを減らす設定を尊重する |

数値は改修の開始基準。実際の長い日本語、端末幅、文字拡大、配色の見え方で調整する。既存のID、理論カードの独自性、お気に入りの3種類、マイ処世術のフォルダー管理、推薦のバックエンド運用は前提として扱う。

## 改修の順番

1. **矛盾・露出・見失いを解消する。** ハート説明、保存用語、Markdown露出、見えない絞込み、仮題名、利用中の購入見出しを修正する。
2. **読む・見つける部分を整える。** 最小文字サイズ、理論一覧の上部、保存付きカード、知識モーダル、PCの基準線を直す。
3. **素材と共通部品を揃える。** タブ、見出し、枠、写真、アイコン、ボタンを共通ルールへ寄せる。画面ごとの色・角丸の追加を減らす。
4. **各画面を仕上げる。** 禄丸の位置、フォルダー表紙の文字、作成フォームの案内、記事の章移動、ランキングの説明を調整する。

最初から全画面を同時に描き直すと、未整理の規則がまた画面ごとの例外になる。まず一覧・詳細・保存の3つの代表画面で基準を決め、その部品を他へ展開する。

## 完成確認の条件

- 320pxで操作名を7〜9pxに縮小しない。長い題名・フォルダー名が読める。
- 保存の説明・形・通知・読み上げ名が一致する。
- お気に入りの0件が「全体の0件」か「絞込みの0件」か分かり、条件を解除できる。
- 読込前・取得失敗時に仮の有料題名が通常カードとして並ばない。
- 記事にMarkdownの制御記号が露出しない。
- 理論一覧の最初の画面で、複数の知識の題名を比較できる。
- 知識のつながりで関連名・説明・読む操作へ無駄なスクロールを挟まない。
- キャラクター・固定ナビ・固定購入バーが操作や本文を覆わない。
- PCの本文・関連・出典の基準線が揃う。
- 既存のID、保存内容、フォルダー、履歴、購入権限を維持する。
- 修正後は無料／完全版／未ログイン、空／多数保存、長文、読込／失敗を代表状態として確認する。
